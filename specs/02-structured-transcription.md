# Spec 02 — Структурированная транскрипция и совместимость API

Модель-исполнитель: **GPT-5.6 Sol** (`gpt-5.6-sol`). При запуске выполнения
этого spec выбирать указанную модель; запись в документе сама модель не переключает.

Статус: запланировано. Зависимости: окружение spec 01; рефакторинг можно выполнить
до запуска очереди spec 03.
Источник: [IMPLEMENTATION_PLAN.md](../IMPLEMENTATION_PLAN.md), разделы
«Что учесть в текущем коде», «Схема данных», «Локальная инфраструктура».

## Результат и границы

VoiceProcessor возвращает структурированные реплики с временными метками.
Старый `POST /transcribe` продолжает принимать файл и отвечать `{"text": ...}`.
Этот этап не устанавливает личности говорящих и не извлекает поручения.

## Что сделать

- Проверить `src/server.py`, `src/call_summary/server.py` и команду Makefile;
  выбрать одну каноническую точку запуска, сохранив документированную совместимость.
- Ввести типизированный результат: упорядоченные реплики с ordinal, start_ms,
  end_ms, text, локальной меткой спикера nullable и форматированный result_text.
- Получать структуру из transcript_segments и speaker_segments до склейки
  в `merge_transcript_with_speakers()`. Не парсить готовую строку обратно.
- Определить преобразование секунд провайдера в миллисекунды и проверку интервалов.
  Процессор возвращает локальное время файла; слой сохранения spec 03 добавляет
  offset_ms ровно один раз и сохраняет время относительно звонка.
- Оставить совместимый строковый интерфейс/обёртку process_ogg для старых вызовов.
  Переиспользовать один форматтер текста, чтобы ответы API не расходились.
- Корректно обрабатывать отсутствие речи, пустую диаризацию и неизвестного спикера;
  отсутствие результата диаризации не должно уничтожать распознанный текст.
- Метки спикеров ограничить фрагментом: SPEAKER_00 не означает постоянного человека.
- Сохранять настройку ASR/диаризации на сервере. provider источника звонка
  не переключает Deepgram/Whisper и не подставляет имя участника.
- Убирать временные файлы на успехе и ошибке, использовать безопасное создание
  временных путей; не блокировать event loop тяжёлой обработкой.
- Процессор принимает локальный временный путь и не знает S3 credentials/endpoint.
  Worker spec 03 скачивает объект через общий S3-адаптер во временный каталог,
  передаёт путь процессору и очищает файл. Не обращаться напрямую к volume MinIO.
- Загрузку моделей выполнять один раз в процессе обработки. Для старого API
  описать выделенный режим или делегирование worker, завершаемое в spec 03.
  Импорт API чтения/MCP не должен автоматически загружать модели.

## Критерии оценки и проверки

| ID | Критерий приёмки | Как проверить |
| --- | --- | --- |
| S02-01 | Структура сохраняет содержание и время | На фиксированных сегментах проверить порядок, текст, интервалы и переходы спикеров |
| S02-02 | Старый API совместим | Отправить .ogg в /transcribe и проверить прежний контракт JSON и формат текста |
| S02-03 | Нет выдуманной личности | Два файла с SPEAKER_00 сохраняют локальные метки, без автоматического person_id |
| S02-04 | Пустые результаты обрабатываются | Проверить тишину и отсутствие speaker_segments: нет падения поиска ближайшего спикера, текст не теряется |
| S02-05 | Ошибки не оставляют временные файлы | Имитировать исключение транскрипции/диаризации и проверить очистку и контролируемую ошибку API |
| S02-06 | Временная шкала корректна | В связке со spec 03 добавить известное смещение к репликам и проверить отсутствие двойного смещения |
| S02-07 | Модели не грузятся на каждый запрос | Проверить счётчиком создание процессора при нескольких запросах; отдельно импорт API чтения без инициализации моделей |

Основные тесты используют заглушки провайдеров. Дополнительно выполнить небольшой
smoke-тест реальной транскрипции при настроенном провайдере; записать режим,
длительность файла и результат. Если ключей нет, отметить smoke как невыполненный.

## Артефакты завершения

Типы результата, обновлённый процессор/форматтер, совместимый endpoint,
унифицированный запуск, фикстуры и результаты S02. Документировать границу между
локальными временными метками процессора и временной шкалой БД.
