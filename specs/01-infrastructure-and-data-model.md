# Spec 01 — Docker, конфигурация, миграции и модели данных

Модель-исполнитель: **GPT-5.6 Sol** (`gpt-5.6-sol`). При запуске выполнения
этого spec выбирать указанную модель; запись в документе сама модель не переключает.

Статус: реализовано; результаты локальных проверок — [отчёт S01](../docs/spec01-verification.md).
Зависимости: нет.
Источник: [IMPLEMENTATION_PLAN.md](../IMPLEMENTATION_PLAN.md), разделы «Решения и границы»,
«Локальная инфраструктура», «Схема данных», «Перенос в Supabase».

## Результат и границы

Воспроизводимое локальное окружение с PostgreSQL и миграциями, готовое для API
и worker следующих этапов. Модель учитывает workspace, внешние источники и дорожки.
На этом этапе не требуется транскрипция, извлечение задач или реальные интеграции.

## Что сделать

- Добавить Dockerfile и Compose: db, minio, api, worker, отдельный запуск миграций
  и идемпотентная инициализация приватного bucket call-audio и доступа приложения.
  Для API/worker подготовить точки запуска; фактическую обработку подключает spec 03.
- Закрепить версию PostgreSQL; не использовать latest. Проверить сборку с Python
  >=3.14 и аудиозависимостями. Основной режим CPU, GPU описать отдельно.
- Закрепить доступный проверенный образ MinIO по версии/digest; проверить команды
  запуска/healthcheck. Не использовать latest или предполагать доступность старого образа.
- Named volumes postgres_data и minio_data; аудиотом подключить только к MinIO.
  API/worker используют S3 по сети, без общего аудиотома. Временные файлы worker
  не являются постоянным хранилищем и очищаются после обработки.
- Настроить healthcheck БД/MinIO, readiness загрузки с проверкой bucket/БД,
  ограниченный connection pool. Готовность чтения текстов не зависит от S3.
- Добавить настройки и `.env.example`: DATABASE_URL, MIGRATION_DATABASE_URL,
  AUDIO_STORAGE_BACKEND=s3, S3_ENDPOINT_URL, S3_REGION, S3_BUCKET,
  S3_ACCESS_KEY_ID, S3_SECRET_ACCESS_KEY, S3_ADDRESSING_STYLE=path, AUDIO_TEMP_DIR,
  провайдеры и ключи, лимиты файлов/worker. Отдельные admin credentials MinIO
  используются при инициализации; приложению выдать доступ к своему bucket.
  Секреты, аудио и содержимое volumes исключить из Git.
- Добавить SQLAlchemy и драйвер PostgreSQL, настроить Alembic как единственную
  историю миграций. Использовать отдельную схему call_summary и серверную роль.
- Создать модели и миграции всех 19 таблиц из раздела «Схема данных» исходного плана:
  workspaces, integration_connections, integration_subscriptions, integration_events,
  meetings, source_sessions, people, person_identities, meeting_participants,
  participant_sessions, meeting_speakers, audio_streams, audio_chunks, chunk_speakers,
  utterances, action_items, action_item_sources, action_item_events, processing_jobs.
  Точные поля и nullability брать из таблицы плана, включая provider и transport.
- Для каждой таблицы, включая связующие: публичный `id UUID NOT NULL UNIQUE
  DEFAULT gen_random_uuid()` и внутренний `int_id BIGINT GENERATED ALWAYS AS
  IDENTITY PRIMARY KEY`. Все FK — BIGINT к int_id; JOIN по внутренним ключам.
- TIMESTAMPTZ для календарного времени, миллисекунды для положения в записи,
  TEXT для текста/внешних ID; JSONB только для дополнительных метаданных.
- Перенести все UNIQUE, CHECK и индексы плана. Особенно `(stream_id, sequence_no)`,
  ключи внешних событий/сеансов/аккаунтов и deduplication_key заданий.
  У action_item_sources свой int_id PK и отдельный UNIQUE пары FK.
- Обеспечить составными FK принадлежность одному workspace; согласованность
  meeting → source_session → stream → chunk → utterance и источников задач
  обеспечить ограничениями либо constraint triggers. Не полагаться только на ORM.
- Определить допустимые статусы и CHECK по kind задания, включая ingestion,
  transcription, finalization, poll/renew_subscription и будущий анализ.
- Добавить идемпотентное создание локального workspace. Не создавать подписки
  или фиктивные авторизованные аккаунты сервисов при старте.
- Добавить Makefile-команды запуска, миграций, логов и остановки с сохранением
  данных; удаление volumes вынести в отдельную явную команду.

## Критерии оценки и проверки

| ID | Критерий приёмки | Как проверить |
| --- | --- | --- |
| S01-01 | Чистое окружение воспроизводимо | На отдельном пустом volume выполнить инструкции README, проверить health/readiness и Alembic head |
| S01-02 | Повтор миграций и инициализации безопасен | Повторить upgrade/создание workspace: нет лишних таблиц и workspace |
| S01-03 | Схема соблюдает ID/FK-контракт | Проверить каталог PostgreSQL для всех таблиц, типов, defaults, identity, PK, UNIQUE и FK; проверить JOIN в репозиториях |
| S01-04 | Ограничения предотвращают повреждение связей | Попытаться создать межпространственный FK, реплику чужого звонка, повтор пары источников задачи и недопустимые интервалы: БД отклоняет запись |
| S01-05 | Дорожки не конфликтуют | Два stream принимают sequence_no=0; повтор sequence_no в одном stream отклоняется |
| S01-06 | Данные переживают остановку | Записать строки и S3-объект, пересоздать контейнеры без удаления postgres_data/minio_data и проверить содержимое через API S3 |
| S01-07 | Конфигурация переносима | Проверить отдельные DSN приложения/миграций, отсутствие абсолютных путей хоста в storage_key и секретов в отслеживаемых файлах |
| S01-08 | Bucket готов без ручной настройки | Дважды выполнить инициализацию: приватный bucket и доступ приложения работают, а анонимное чтение запрещено |
| S01-09 | Нет зависимости от общего файлового тома | API и worker видят один объект через S3; проверить Compose mounts, затем отключить MinIO: загрузка не готова, чтение сохранённых текстов доступно после spec 05 |

Интеграционные проверки выполняются на PostgreSQL, не SQLite. Функциональность
worker проверяется в spec 03; этот этап не считается доказательством её готовности.

## Артефакты завершения

Docker/Compose, настройки, ORM-модели, Alembic migrations, команды Makefile,
README запуска/остановки/backup и результаты проверок S01. Описать выбранную
версии PostgreSQL/образа MinIO, серверные права, S3 endpoint для контейнеров/хоста,
инициализацию и резервное копирование объектов. Обновления модели согласовать с исходным планом.
