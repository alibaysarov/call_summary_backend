# Spec 05 — Ограниченные запросы чтения и MCP

Модель-исполнитель: **GPT-5.6 Sol** (`gpt-5.6-sol`). При запуске выполнения
этого spec выбирать указанную модель; запись в документе сама модель не переключает.

Статус: запланировано. Зависимости: specs 01–04.
Источник: [IMPLEMENTATION_PLAN.md](../IMPLEMENTATION_PLAN.md), разделы
«API и последующий MCP», «Схема данных», «Перенос в Supabase».

## Результат и границы

ChatGPT получает задачи и нужные фрагменты звонков через MCP без загрузки всей
истории. Сначала обычные запросы PostgreSQL и поиск по тексту, без embeddings.

## Что сделать

- Реализовать общие сервисы чтения для HTTP и MCP: задачи по человеку/звонку/статусу,
  расшифровка по интервалу, поиск звонков по тексту и фильтрам даты/источника.
- Добавить разрешение имени в person: при неоднозначности вернуть кандидатов с
  публичными UUID и контекстом для выбора; не выбирать первого Али автоматически.
- Предоставить tools `get_person_tasks`, `get_meeting_transcript`, `search_meetings`.
  Описать входы, выходы и ошибки; не предоставлять произвольный SQL.
- Публичные ID — UUID; сервис переводит их во внутренние BIGINT. Все чтения и
  JOIN ограничены workspace; provider-filter не заменяет проверку доступа.
- Задать конфигурируемые верхние лимиты записей, размера цитат и ответа.
  Начальный ориентир — 20 задач на страницу. Возвращать cursor, has_more,
  источники и статус полноты обработки; порядок пагинации детерминированный.
- Для расшифровки запрашивать временной диапазон и ограниченное окно соседних
  реплик. Большой звонок читается страницами, не одним ответом по умолчанию.
- Для поручений возвращать описание, ответственного, срок, статус, дату/ID звонка,
  короткую подтверждающую цитату и время реплики. Не выдавать страницу за полный список.
- Проверить планы запросов и индексы на репрезентативных данных, исправить
  выявленные проблемы. Зафиксировать метод текстового поиска и ограничения качества.
- MCP/чтение не загружают речевые модели и не запускают транскрипцию.
- Текстовые запросы используют PostgreSQL без зависимости от доступности S3.
  Не выдавать S3 credentials или постоянные публичные ссылки на приватное аудио;
  метаданные источника — ID звонка/реплики и временные метки. Выдача самого аудио
  не является обязательной функцией этого этапа.
- Перед фактическим подключением проверить актуальную официальную документацию
  OpenAI, транспорт/доступность MCP и способ аутентификации. Реализовать выбранный
  способ и описать подключение/обновление инструментов. Не подменять проверку
  реального ChatGPT тестом одного HTTP endpoint.
- До удалённого доступа обеспечить аутентификацию и членство в workspace;
  локальный single-workspace режим не выдавать за готовую многопользовательскую защиту.

## Критерии оценки и проверки

| ID | Критерий приёмки | Как проверить |
| --- | --- | --- |
| S05-01 | Вопрос о задачах даёт подтверждённый ответ | На подготовленном звонке запросить задачи Али: все ожидаемые поручения доступны по страницам, есть цитаты, нет полного транскрипта |
| S05-02 | Неоднозначность имени видна | Два человека Али дают кандидатов; подтверждённые аккаунты одного человека объединяют его задачи внутри workspace |
| S05-03 | Размер ответа ограничен | Запросить большой звонок/список задач и чрезмерный limit: применяются лимиты, доступны has_more/cursor |
| S05-04 | Пагинация стабильна | На фиксированном наборе с одинаковыми timestamps пройти страницы без пропусков/повторов; документировать поведение при изменении данных |
| S05-05 | Поиск возвращает проверяемый контекст | Запрос по теме/датам/provider даёт подходящие звонки и короткие источники; при недостатке данных нет выдуманного результата |
| S05-06 | Изоляция и UUID соблюдены | Передать чужие UUID, изменить фильтры, запросить данные второго workspace: доступа нет; внутренние ключи не раскрываются |
| S05-07 | Неполнота не скрывается | Запросить обрабатываемый/неполный звонок: статус и ограничения явно присутствуют |
| S05-08 | Запросы измерены | Снять EXPLAIN (ANALYZE, BUFFERS) и задержки основных чтений на тестовой БД; приложить объём данных и конфигурацию |
| S05-09 | MCP работает как интеграция | Проверить обнаружение tools и вызовы через MCP-клиент, затем сквозной вопрос в ChatGPT при доступном подключении |
| S05-10 | Чтение независимо от ASR | Запустить сервер чтения без моделей/ключа ASR и прочитать ранее сохранённые данные |
| S05-11 | Чтение независимо от S3 | Отключить MinIO после обработки: задачи/текст доступны через HTTP/MCP, ответы не раскрывают ключи хранилища |

Интеграционные проверки — PostgreSQL и фиксированные данные. Если реальное
подключение ChatGPT недоступно, отметить S05-09 частично выполненным; не считать
документацию подключения доказательством сквозной проверки.

## Артефакты завершения

Сервисы/HTTP/MCP-контракты, лимиты и пагинация, инструкции подключения с актуальными
официальными ссылками, тесты S05, результаты планов/замеров и сквозного сценария.
